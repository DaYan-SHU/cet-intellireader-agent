System Architecture · cet-intellireader-agent v0.1.0

四六级英语阅读智能命题系统

输入一段中／英文素材，自动产出四级或六级的整套阅读理解模拟题：文章、5 道选择题、答案精解、词汇表与写作大纲。核心是一条带双质检回环的 LangGraph 多节点工作流。

LAYER 3
节点能力层
9 Nodes

① 联网搜索

search_node

Tavily 取前 3 条结果，交 LLM 改写成 400–600 字中文素材；模块缺失或失败则原样放行。

② 素材分析

analyze_text

语言检测 + 体裁提示，产出「中文理解摘要 + 英文大纲」，再由正则解析器拆成两个字段。

③ 生成文章

generate_article

按级别控制词数（四级 400–450 / 六级 450–550），严格依大纲展开，携带上轮修改意见。

④ 文章质检

check_article_quality

校验词数、主题一致性、语法与中式英语、是否适合作阅读材料，输出 PASS 或修改建议。

⑤ 生成题目

generate_questions

5 道四选一，编号 46–50，主旨 1 + 细节 2 + 推理 1 + 词汇 1，每题带答题留白。

⑥ 题目质检

check_questions_quality

校验题量是否为 5、题型配比、留白完整性、干扰项合理性。

⑦ 答案与解析

generate_answers

逐题给出正确选项与中文解析，说明正确项依据与干扰项排除理由。

⑧ 词汇表

generate_vocabulary

抽取 10–15 个核心词，制表符三列（词 / 词性 / 释义），按字母序，便于转 Word 表格。

⑨ 整合输出

finalize

按固定 6 个区块拼装最终文档，include_vocab 从源头决定是否包含词汇表章节。

LAYER 4
基础支撑
Config · Utils

LLM 客户端

config/settings.py

ChatDeepSeek(deepseek-chat, temperature 0.7, max_retries 2)；.env 双路径加载，兼容 PyInstaller 解压目录。

检索工具

utils/search.py

封装 TavilySearch（max_results 3）与「检索结果 → 中文素材」摘要链路，缺 Key 时静默降级。

文本工具

utils/helpers.py

detect_language：中文字符占比 > 30% 判为中文，据此选择分析提示词。

文档导出

utils/export.py

python-docx 生成 Word：标题块解析、【章节】转二级标题、词汇表转三列表格、题号缩进。

主题样式

ui/theme.py

品牌配色（#d97757 强调色 / #faf9f5 底色）与字体回退，仅注入 CSS、不碰 DOM。

EXTERNAL
外部服务
3rd Party

DeepSeek API 必需

POST api.deepseek.com/chat/completions

模型 deepseek-chat，全部 8 处生成／质检调用的唯一推理来源。

Tavily Search 可选

POST api.tavily.com/search

仅当用户勾选「启用联网搜索」且填写主题时调用；无 Key 则走纯素材链路。

本地环境变量

.env → DEEPSEEK_API_KEY / TAVILY_API_KEY

打包态依次查找 _MEIPASS 与 exe 同级目录；Windows 代理下自动 NO_PROXY 直连 API 域名。

状态契约 AgentState

节点间唯一数据通道
分组字段作用
输入 input_text · level · genre 原始素材、四级／六级、体裁提示（自动 / 议论文 / 说明文 / 叙事文）

输出 final_output · include_vocab 拼装完成的最终文档；是否输出词汇表章节

运行形态对照

同一内核，四种壳
形态入口流程引擎导出端口适用场景

一致性策略：Node 版没有复用 Python 代码，而是把 core/nodes.py 的提示词与解析函数逐字迁移，并用手写的 while 循环复刻 LangGraph 的拓扑与重试语义。好处是零依赖、易部署；代价是两套代码需同步维护——任何提示词调整都要改两处。
